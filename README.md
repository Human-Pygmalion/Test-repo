테스트 단위별로 폴더를 나누어 관리합니다.

## 구성

| 폴더 | 내용 |
| --- | --- |
| [Ebimu/](Ebimu/) | 센서 통신 및 실시간 모니터링 스크립트 — [사용법](Ebimu/README.md) |

```bash

```

## 저장소 규칙

### 1. 테스트 단위별로 폴더를 만든다

새로운 하드웨어 / 테스트 항목이 생기면 루트에 그 단위의 폴더를 하나 만든다.
서로 다른 테스트 대상의 코드를 한 폴더에 섞지 않는다.

```
Test-repo/
├── README.md          ← 저장소 전체 설명 + 규칙 (이 파일)
├── requirements.txt   ← 전체 의존성
├── Ebimu/             ← 테스트 단위 1 (센서 통신)
│   ├── README.md
│   └── *.py
└── <NewTarget>/       ← 테스트 단위 2
    ├── README.md
    └── *.py
```

### 2. 폴더마다 README.md 를 둔다

각 테스트 폴더에는 반드시 `README.md` 를 두고 아래 항목을 적는다.

- 무엇을 테스트하는지 (대상 장비 / 목적)
- 각 스크립트 파일의 역할
- **실행 명령어** — 옵션별로 복사해서 바로 붙여넣을 수 있는 형태로
- 준비물 (배선, 포트, 권한, 보레이트 등 하드웨어 조건)
- 주의사항 (되돌릴 수 없는 동작, 확인이 필요한 명령 등)

루트 README 의 `## 구성` 에도 새 폴더를 한 줄 추가하고 폴더 README 로 링크를 건다.

### 3. 패키지는 주석으로 용도를 표기한다

`requirements.txt` 에 패키지를 추가할 때는 **어느 테스트에서 왜 쓰는지**를 주석으로 남긴다.
버전은 가능하면 하한(`>=`)을 명시한다.

```python
# =========================================
# 테스트 프로젝트 의존성
# =========================================

# [Ebimu] 시리얼 통신 — Ebimu_cmd.py / Ebimu_live.py
pyserial>=3.5
```

코드 안에서도 표준 라이브러리가 아닌 패키지를 import 할 때는
용도를 한 줄 주석으로 적고, 없을 때의 안내 메시지를 함께 둔다.

```python
try:
    import serial          # pyserial: EBIMU 시리얼 통신
except ImportError:
    sys.exit("pyserial 이 없습니다.  pip install pyserial")
```

### 4. 스크립트 상단에 docstring 을 쓴다

각 스크립트의 맨 위 docstring 에 목적 / 사용법 예시 / 하드웨어 요구사항 / 주의사항을 적는다.
`--help` 만 봐도 쓸 수 있게 argparse 의 `help` 문구도 빠짐없이 채운다.

### 5. 하드웨어를 바꾸는 동작은 기본으로 막는다

공장초기화, 통신속도 변경, 캘리브레이션처럼 되돌리기 어렵거나
사람이 직접 개입해야 하는 명령은 기본 동작에 넣지 않는다.
필요하면 별도 플래그(예: `--include-cal`)나 실행 중 확인 절차를 거치게 하고,
그 사실을 폴더 README 에 명시한다.
